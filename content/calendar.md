# Posting calendar

One post per day. The day of the week picks the format; the guardrail below can
override it.

| Day | Format (`kind`) | What it is |
| --- | --- | --- |
| Monday | `trending` | A developer topic moving this week, with my practical take — never a summary of someone else's article |
| Tuesday | `ai-vs-human` | One task solved twice: how I would do it purely by hand vs. with AI assistance — honest about time saved *and* where AI got it wrong |
| Wednesday | `challenge` | A real problem hit recently and how it was solved |
| Thursday | `trending` | Same as Monday, different topic |
| Friday | `ai-vs-human` | Same as Tuesday, different task |
| Saturday | `learnings` | What this week taught me — techniques, patterns, mistakes |
| Sunday | `challenge` | Weekly recap: the week's hardest problem in depth |

## The honesty guardrail (non-negotiable)

`challenge`, `learnings` and `ai-vs-human` posts describe **my** experience, so they may
only be written from real source material:

1. Notes I have dropped in `content/notes.md`
2. Actual recent activity in my GitHub repositories (commits, PRs, issues)

**If neither contains enough material for the day's format, the writer must fall back to
a `trending` post instead.** Inventing a personal anecdote, a bug I never hit, or a
project that does not exist is never acceptable — one fabricated "war story" costs more
credibility than a hundred good posts earn.

## Quality bar

- One specific idea per post, 500–900 words
- Concrete artefacts: real commands, real error text, real numbers
- A takeaway the reader can apply, stated plainly at the end
- No engagement bait, no "in today's fast-paced world", no emoji walls
